# บันทึกผลการตรวจ Integration รอบ 19 ตุลาคม 2026

## ขอบเขตและสภาพแวดล้อม

- วันที่: 19 ตุลาคม 2026 (เวลาไทย)
- Runtime: Node.js v24.19.0, Windows
- วิธีตรวจ: manual API integration smoke test จาก source ปัจจุบัน
- ฐานข้อมูล: SQLite ใหม่ในโฟลเดอร์ชั่วคราว แยกจาก `backend/cafe_pos.db` ของร้าน
- บัญชี: สร้างบัญชีทดสอบ owner/barista ในฐานข้อมูลชั่วคราว; ไม่ใช้หรือบันทึก credential ของผู้ใช้จริง
- ขอบเขต: login, สร้าง order, อ่านคิว, เปลี่ยนสถานะครบลำดับ และอ่านรายงานยอดขาย

## ผลที่สังเกตได้

| ขั้นตอน | ผลที่ได้รับ |
|---|---|
| เข้าสู่ระบบด้วย role owner | สำเร็จ; `/api/auth/me` ระบุ role `owner` |
| สร้างลาเต้ 1 แก้ว สาขา 1, ร้อน, S, หวาน 50%, ชำระเงินสด | HTTP 201; order `POS-20261019-01-0004`, queue 4, ยอด 60 บาท, สถานะเริ่มต้น `pending` |
| อ่าน `/api/orders/queue?branchId=1` | พบ order ที่เพิ่งสร้างในคิว |
| เปลี่ยนสถานะ `cooking` → `ready` → `completed` | API รับการเปลี่ยนทั้งสามขั้นตามลำดับ |
| อ่าน `/api/reports/sales?branchId=1&period=all` | รายงานมี order ที่สร้าง; พบ 4 completed orders และยอดรวม 460 บาทในฐานข้อมูลทดสอบ |

**ผลของกรณี INT-API-01:** ผ่านสำหรับ flow API ที่ระบุไว้ด้านบนในฐานข้อมูลแยก

## ข้อจำกัดของหลักฐาน

นี่เป็น smoke test ระดับ API ไม่ใช่การซ้อม/บันทึกภาพ live demo ผ่านหน้าจอ และไม่ยืนยันพฤติกรรม polling, การแสดงผล UI, performance, concurrency หรือ fault-injection. กรณี TC-01–TC-14 ใน [wk13 test plan](./wk13-test-cases.md) ยังคงต้อง execute ตามขั้นตอนของแต่ละกรณี; ผลนี้ไม่เปลี่ยน TC ที่ยังไม่รันเป็น PASS. ฐานข้อมูลทดสอบอยู่ในโฟลเดอร์ชั่วคราวและแยกจากฐานข้อมูลใช้งานจริง.

> บันทึกนี้เก็บผล smoke test ที่ทำก่อนการเพิ่ม barista stock overview และสูตรน้ำตาล จึงไม่ใช่หลักฐานทดสอบความสามารถใหม่สองส่วนนี้; ดู TC-13/TC-14 ใน test plan ซึ่งยังไม่รัน
