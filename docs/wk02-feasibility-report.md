## 1. รายงานการศึกษาความเป็นไปได้ (TELOS Feasibility Analysis)

### 1.1 ความเป็นไปได้ทางเทคนิค (Technical Feasibility)

- **สถาปัตยกรรมระบบ (System Architecture)**:
  - ใช้ Monolithic Architecture รัน Node.js/Express บนเครื่องเดียว พร้อม SQLite เป็นฐานข้อมูล
  - Frontend เป็น React SPA (Single Page Application) ที่ Build แล้ว Serve จาก Express
  - ไม่ต้องการ Cloud Server สำหรับระยะเริ่มต้น ลดความซับซ้อนในการ Deploy
- **ฮาร์ดแวร์และเทคโนโลยี (Hardware)**:
  - **POS หน้าร้าน**: PC/Laptop หรือ Tablet ความกว้างหน้าจอ ≥ 768px + Chrome Browser
  - **หน้าจอบาริสต้า**: Tablet แยกต่างหาก หรือใช้ Tab แยกในเบราว์เซอร์เดียวกัน
  - **Software Stack**: React 19 + Vite (Frontend), Node.js + Express (Backend), SQLite / MySQL (Database)
- **ความเป็นไปได้ทางเทคนิค**: **สูง** — เทคโนโลยีที่ใช้ทั้งหมดเป็น Open Source ไม่มีค่าลิขสิทธิ์ ทีมมีความรู้จากการเรียนในวิชา

---

### 1.2 ความเป็นไปได้ทางเศรษฐศาสตร์ (Economic Feasibility)

#### 1.2.1 ต้นทุนโครงการ (Cost Estimation)

1. **เงินลงทุนเริ่มต้น (CAPEX)**:
   - ค่าพัฒนาซอฟต์แวร์: **0 บาท** (ทีมนักศึกษาพัฒนาเอง)
   - ค่า Hardware (PC/Tablet สำหรับ POS): **15,000 – 25,000 บาท**
   - **รวม CAPEX: ประมาณ 15,000 – 25,000 บาท**
2. **ค่าใช้จ่ายรายเดือน (OPEX)**:
   - ค่าไฟฟ้าและ Wi-Fi ในร้าน: ไม่มีค่าใช้จ่ายเพิ่มเติม (ใช้ Infrastructure ที่มีอยู่แล้ว)
   - **รวม OPEX: ~0 บาท/เดือน** (สำหรับร้านสาขาเดียว)

#### 1.2.2 ผลประโยชน์ทางการเงิน (Expected Financial Benefits)

- **ลดเวลาต่อคิว**: ลดเวลารับออเดอร์จาก 3-5 นาที เหลือ < 1 นาที เพิ่มจำนวนลูกค้าในชั่วโมง Peak
- **ลดข้อผิดพลาดออเดอร์**: ระบบบังคับเลือกขนาด/ความหวาน ลดการทำเครื่องดื่มผิดพลาด ~80%
- **ประหยัดกระดาษ**: ลดการจดโพยมือ ลดความสูญเสียออเดอร์ตกหล่น

#### 1.2.3 ตัวชี้วัดทางการเงิน

- **ระยะเวลาคืนทุน (Payback Period)**: ภายใน **2-3 เดือน** (ค่า Hardware เท่านั้น)
- **ROI**: สูงมาก เนื่องจากค่าพัฒนา Software = 0

---

### 1.3 ความเป็นไปได้ทางการปฏิบัติงาน (Operational Feasibility)

- **กระบวนการทำงานใหม่**:
  - แคชเชียร์กดเลือกเมนูบนจอ Touchscreen พร้อม Popup เลือกขนาด/หวาน/ท็อปปิง
  - ออเดอร์ปรากฏบนหน้าจอบาริสต้าโดยอัตโนมัติ ภายใน 5 วินาที (Polling ทุก 3 วินาที)
  - บาริสต้ากดเปลี่ยนสถานะ: รอทำ → กำลังทำ → พร้อมรับ → เสร็จสิ้น
- **การยอมรับและการฝึกอบรม**:
  - UI ออกแบบให้ใช้งานง่าย พนักงานใหม่สามารถใช้งานได้ภายใน 5 นาที (ตาม NFR-03)
  - หน้าจอ Responsive รองรับทั้ง Tablet และ Desktop (ตาม NFR-04)

## 2. แผนภาพ BPMN กระบวนการสั่งกาแฟ (Business Process Model and Notation)

### 2.1 BPMN แบบ As-Is (กระบวนการเดิมก่อนมีระบบ POS)

| ลำดับ | ผู้ดำเนินการ | ขั้นตอน |
|---|---|---|
| 1 | ลูกค้า | สั่งรายการเครื่องดื่มกับพนักงาน (บอกปากเปล่า) |
| 2 | พนักงาน | จดรายการลงกระดาษ แจ้งราคาด้วยความจำหรือดูเมนู |
| 3 | ลูกค้า | จ่ายเงินสด |
| 4 | พนักงาน | ทอนเงิน เขียนโพยส่งบาริสต้า บันทึกรายรับด้วยมือ |
| 5 | บาริสต้า | รับโพย ชงเครื่องดื่ม เรียกชื่อลูกค้า |
| 6 | ลูกค้า | รับเครื่องดื่ม |

**ปัญหาของกระบวนการเดิม:**
- ลายมืออ่านไม่ออก / ออเดอร์ตกหล่น
- ยอดเงินในลิ้นชักไม่ตรงกับรายการขาย
- สรุปยอดขายปลายวันใช้เวลานาน

### 2.2 BPMN แบบ To-Be (กระบวนการใหม่ด้วยระบบ POS)

| ลำดับ | ผู้ดำเนินการ | ขั้นตอน |
|---|---|---|
| 1 | ลูกค้า | สั่งรายการกับแคชเชียร์ |
| 2 | แคชเชียร์ | กดเลือกเมนูบนจอ POS → เลือกขนาด/หวาน/ท็อปปิง |
| 3 | ระบบ POS | คำนวณยอดรวมอัตโนมัติ แสดงบนหน้าจอ |
| 4 | แคชเชียร์ | เลือกวิธีชำระเงิน (Cash/QR/โอน) → ยืนยันออเดอร์ |
| 5 | ระบบ POS | สร้างเลขคิว #001 แสดงใบเสร็จ ส่งคิวไปหน้าจอบาริสต้า |
| 6 | บาริสต้า | รับออเดอร์บนจอ → กด "เริ่มทำ" → ชงกาแฟ → กด "พร้อมรับ" |
| 7 | แคชเชียร์ | ขานเรียกคิว #001 ส่งเครื่องดื่มให้ลูกค้า |

### 2.3 ตารางเปรียบเทียบ As-Is vs To-Be

| หัวข้อ | กระบวนการเดิม (As-Is) | กระบวนการใหม่ (To-Be) | ผลลัพธ์ |
|:---|:---|:---|:---|
| **การรับออเดอร์** | จดมือลงกระดาษ | กดบนจอ POS | ออเดอร์ถูกต้อง 100% |
| **การส่งคำสั่งเข้าครัว** | เดินส่งโพยกระดาษ | ส่งเข้าจอบาริสต้าอัตโนมัติ | ไม่มีออเดอร์ตกหล่น |
| **การชำระเงิน** | นับเงินสด คีย์ย้อนหลัง | Cash/QR/โอน บันทึกอัตโนมัติ | ยอดเงินตรงแม่นยำ |
| **การติดตามคิว** | ขานชื่อ/จำ | เลขคิว #001, #002... | ลดการสับสน ลูกค้าพอใจ |
