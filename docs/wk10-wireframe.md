## 8. Input/Output Design Summary

| หน้าจอ                 | Input                                    | Output / การแสดงผล                  |
| ---------------------- | ---------------------------------------- | ----------------------------------- |
| **CashierView**        | คลิกเลือกเมนู, กรองหมวดหมู่, สลับสาขา    | แสดงการ์ดเมนู 4 หมวด, ตะกร้าสินค้า  |
| **CustomizationModal** | เลือกขนาด (บังคับ), หวาน, ท็อปปิง, จำนวน | แสดงยอดรวมสินค้าแบบ real-time       |
| **CartSidebar**        | เลือกวิธีชำระเงิน, กดยืนยัน              | แสดงรายการ, ยอดรวม, ปุ่มชำระ        |
| **ReceiptModal**       | —                                        | เลขออเดอร์, เลขคิว, ยอดเงิน, รายการ |
| **BaristaView**        | กดเปลี่ยนสถานะ (เริ่มทำ/พร้อมรับ/เสร็จ), เปิดดูสต็อกแบบ read-only | คิว polling ทุก 3 วินาที; stock overview poll ทุก 30 วินาทีเมื่อเปิด |
| **OwnerView**          | กรองตามสาขา, ค้นหาออเดอร์, เปลี่ยนแท็บ   | สรุปยอดขาย, กราฟ Top 5, ประวัติคิว  |
| **MenuManager**        | ฟอร์มเพิ่ม/แก้ไขเมนู, วิธีชงสำหรับบาริสต้า, อัปโหลดรูปภาพ | รายการเมนู, ราคาฐาน, สถานะขาย |

### กฎ Validation ที่ระบบบังคับ (FR-03, FR-04)

- เครื่องดื่มต้องมีตัวเลือกที่จำเป็นตามชนิดสินค้า โดย UI บังคับประเภทและขนาด; กฎ server ตรวจ option ที่ส่งและสูตรสต็อกที่ตรงกัน
- ตะกร้าต้องมีสินค้าอย่างน้อย **1 รายการ** ก่อนยืนยัน
- ต้องเลือก **วิธีชำระเงิน** ก่อนกดยืนยัน
- บาริสต้าหรือ owner เปลี่ยนสถานะได้ทีละขั้น; ย้อนหรือข้ามขั้นไม่ได้ (FR-08)
- การสร้างเมนูใหม่ต้องระบุ **ชื่อ, หมวดหมู่ และราคาฐาน** ให้ครบถ้วน
