## 1. บทนำ (Introduction)

### 1.1 ภาพรวมระบบ

ระบบจัดการออเดอร์ร้านกาแฟพัฒนาขึ้นเพื่อเปลี่ยนกระบวนการรับออเดอร์จากกระดาษไปสู่ระบบดิจิทัล ช่วยลดข้อผิดพลาดในการจดออเดอร์ เพิ่มความเร็วในการส่งข้อมูลไปยังบาริสต้า และช่วยให้เจ้าของร้านติดตามยอดขายและสต็อกวัตถุดิบได้แบบเรียลไทม์

### 1.2 วัตถุประสงค์

- เพื่อลดอัตราการทำเครื่องดื่มผิดพลาดอันเกิดจากการจดออเดอร์ไม่ชัดเจน
- เพื่อลดเวลาในการส่งผ่านข้อมูลออเดอร์ระหว่างพนักงานหน้าร้านและบาริสต้า
- เพื่อให้สามารถตรวจสอบรายงานยอดขายและแจ้งเตือนวัตถุดิบใกล้หมดได้อย่างแม่นยำ

### 1.3 ผู้มีส่วนได้ส่วนเสีย (Stakeholders)

- **เจ้าของร้าน:** ดูรายงานยอดขาย จัดการสต็อก และตั้งค่าเมนู
- **พนักงานรับออเดอร์ (Cashier):** รับออเดอร์ คำนวณเงิน และแจ้งสถานะแก่ลูกค้า
- **บาริสต้า:** ดูรายการคิวออเดอร์ รายละเอียดการชง และอัปเดตสถานะการทำเครื่องดื่ม

## 2. ขอบเขตระบบ (Scope)

### สิ่งที่ระบบจะทำ

- แสดงเมนู ราคา ขนาด ระดับหวาน และท็อปปิง
- รับและบันทึกออเดอร์
- คำนวณยอดรวมและบันทึกการชำระเงิน
- แสดงคิวและสถานะออเดอร์แก่พนักงานและบาริสต้า
- แจ้งเตือนเมื่อออเดอร์พร้อมรับ
- ตัดสต็อกวัตถุดิบและแจ้งเตือนเมื่อใกล้หมด
- แสดงรายงานยอดขายตามวันที่และสาขา

### สิ่งที่ระบบจะไม่ทำ

- ระบบบัญชีและภาษีแบบเต็มรูปแบบ
- ระบบจัดส่งสินค้าโดยไรเดอร์
- ระบบจัดซื้อวัตถุดิบอัตโนมัติ
- ระบบคำนวณเงินเดือนพนักงาน

## 3. Functional Requirements

| รหัส  | Functional Requirement                                                                            | เกณฑ์ตรวจสอบ                                                                      |
| ----- | ------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| FR-01 | ระบบต้องแสดงเมนูที่เปิดขายพร้อมชื่อและราคา                                                        | เปิดหน้ารับออเดอร์และตรวจสอบรายการเมนู                                            |
| FR-02 | ระบบต้องให้พนักงานเลือกขนาด ระดับหวาน และท็อปปิงได้                                               | สร้างออเดอร์และตรวจสอบรายละเอียดที่เลือก                                          |
| FR-03 | ระบบต้องตรวจสอบข้อมูลที่จำเป็นก่อนยืนยันออเดอร์                                                   | กดยืนยันโดยไม่กรอกข้อมูลและตรวจสอบข้อความแจ้งเตือน                                |
| FR-04 | ระบบต้องสร้างเลขออเดอร์และเลขคิวที่ไม่ซ้ำกัน                                                      | สร้างออเดอร์ 100 รายการแล้วตรวจสอบเลขซ้ำ                                          |
| FR-05 | ระบบต้องคำนวณราคาสินค้า ท็อปปิง ส่วนลด และยอดสุทธิอัตโนมัติ                                       | เปรียบเทียบยอดที่ระบบคำนวณกับสูตรราคาที่กำหนด                                     |
| FR-06 | ระบบต้องบันทึกวิธีชำระเงิน ได้แก่ เงินสด โอน และ QR Payment                                       | เลือกวิธีชำระเงินแต่ละแบบและตรวจสอบข้อมูลที่บันทึก                                |
| FR-07 | ระบบต้องส่งออเดอร์ไปยังหน้าจอบาริสต้าพร้อมรายละเอียดครบถ้วน                                       | ยืนยันออเดอร์และตรวจสอบหน้าจอบาริสต้า                                             |
| FR-08 | ระบบต้องให้บาริสต้าปรับสถานะเป็น รอทำ กำลังทำ และพร้อมรับ                                         | เปลี่ยนสถานะและตรวจสอบว่าผู้ใช้เห็นสถานะล่าสุด                                    |
| FR-09 | ระบบต้องตัดสต็อกวัตถุดิบตามสูตรเครื่องดื่มอัตโนมัติ และแจ้งเตือนเมื่อวัตถุดิบต่ำกว่าเกณฑ์ที่กำหนด | ทำการสั่งซื้อเครื่องดื่ม และตรวจสอบการตัดจำนวนวัตถุดิบในระบบพร้อมข้อความแจ้งเตือน |
| FR-10 | ระบบต้องแสดงรายงานยอดขายรวม ยอดขายแยกตามสาขา และเมนูขายดี ตามช่วงวันที่ที่กำหนดได้                | สุ่มเลือกช่วงวันที่ และตรวจสอบความถูกต้องของยอดขายและรายการเมนูขายดี              |

## 4. Non-functional Requirements

| รหัส   | Non-functional Requirement                                                                      | เกณฑ์ตรวจสอบ                        |
| ------ | ----------------------------------------------------------------------------------------------- | ----------------------------------- |
| NFR-01 | ระบบต้องเปิดหน้ารับออเดอร์ภายใน 2 วินาที อย่างน้อย 19 จาก 20 ครั้ง                              | จับเวลาการเปิดหน้าจอ 20 ครั้ง       |
| NFR-02 | ระบบต้องส่งออเดอร์ไปหน้าจอบาริสต้าภายใน 5 วินาที อย่างน้อย 19 จาก 20 ครั้ง                      | จับเวลาตั้งแต่กดยืนยันจนรายการปรากฏ |
| NFR-03 | ผู้ใช้ใหม่ต้องสร้างออเดอร์สำเร็จอย่างน้อย 4 จาก 5 ครั้ง หลังได้รับคำแนะนำไม่เกิน 5 นาที         | ให้ผู้ใช้ทดลองสร้างออเดอร์ 5 รอบ    |
| NFR-04 | ระบบต้องใช้งานฟังก์ชันหลักได้บนแท็บเล็ตทั่วไปที่ใช้ Chrome และมีหน้าจอกว้างอย่างน้อย 768 พิกเซล | ทดสอบบนแท็บเล็ตอย่างน้อย 2 รุ่น     |

## 5. ข้อจำกัด (Constraints)

- ต้องพัฒนาระบบให้เริ่มใช้งานได้ภายใน 3 เดือน
- งบประมาณมีจำกัด จึงไม่ซื้อฮาร์ดแวร์เฉพาะทาง
- ระบบต้องใช้งานบนแท็บเล็ตทั่วไปได้
- ระยะแรกต้องรองรับ 3 สาขา และผู้ใช้งานพร้อมกัน 20 คน
- ร้านต้องจัดเตรียมข้อมูลเมนู ราคา สูตรวัตถุดิบ และบัญชีผู้ใช้ก่อนเริ่มใช้งาน
- การชำระเงินผ่าน QR ขึ้นอยู่กับผู้ให้บริการที่ร้านเลือก

## 6. สรุปการสัมภาษณ์ (Interview Summary)

### สรุปผลการวิเคราะห์

ปัญหาหลักคือการจดออเดอร์ผิดและการส่งข้อมูลไปยังบาริสต้าล่าช้า ความต้องการที่สำคัญคือการเลือกเมนูแบบมีตัวเลือก การแสดงคิว การติดตามสถานะ การจัดการสต็อก และรายงานยอดขาย ผลการสัมภาษณ์ถูกแปลงเป็น Functional Requirements 10 ข้อ และ Non-functional Requirements 4 ข้อ โดยทุกข้อมีเกณฑ์ตรวจสอบที่ชัดเจน
