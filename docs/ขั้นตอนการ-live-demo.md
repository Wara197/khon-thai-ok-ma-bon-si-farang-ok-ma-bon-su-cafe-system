# ขั้นตอนการ Live Demo ระบบ Coffee Shop POS

เอกสารนี้เป็นลำดับการสาธิตระบบสำหรับการนำเสนอ ใช้เวลาประมาณ 2–3 นาที ไม่ใช่บันทึกผลการทดสอบ

## 1. เตรียมระบบก่อนวันนำเสนอ

1. เปิด Terminal ที่โฟลเดอร์ `project/`
2. ติดตั้ง dependencies และ build หน้าเว็บ หากยังไม่ได้เตรียมเครื่อง:
   ```bash
   npm run install:all
   npm run build:frontend
   ```
3. เริ่มระบบ:
   ```bash
   npm start
   ```
4. เปิด `http://localhost:3000/` และตรวจว่าหน้าเข้าสู่ระบบแสดงผล
5. เตรียมบัญชีสำหรับ role **Cashier**, **Barista** และ **Owner** ให้พร้อม โดยใช้บัญชีทดสอบที่ทีมตรวจสอบแล้ว
6. เตรียมข้อมูลเมนู/วัตถุดิบสำหรับสาธิต และตรวจว่าไม่มีข้อมูลจริงหรือข้อมูลส่วนตัวที่ไม่ควรแสดง
7. เปิดแท็บหรือหน้าต่างเบราว์เซอร์แยกสำหรับแต่ละ role เพื่อสลับการสาธิตได้รวดเร็ว
8. เตรียมภาพหน้าจอหรือวิดีโอจากระบบที่ทำงานจริงไว้เป็นแผนสำรอง กรณีระบบหรือเครือข่ายขัดข้อง

## 2. ลำดับการสาธิต

### ขั้นที่ 1: รับออเดอร์ในหน้า Cashier

1. เข้าสู่ระบบด้วยบัญชี Cashier
2. แสดงหมวดหมู่และรายการเมนู
3. เลือกเครื่องดื่ม แล้วแสดงตัวเลือก เช่น ขนาด ความหวาน หรือท็อปปิง
4. เพิ่มสินค้าในตะกร้าและแสดงยอดรวม
5. ยืนยันออเดอร์และแสดงเลขออเดอร์กับเลขคิว

**คำอธิบายประกอบ:** หน้า Cashier ส่งข้อมูลออเดอร์ไป backend ระบบตรวจข้อมูลและบันทึกออเดอร์พร้อมรายการสินค้า

### ขั้นที่ 2: ติดตามคิวในหน้า Barista

1. สลับไปยังหน้า Barista
2. แสดงออเดอร์ที่เพิ่งสร้าง หากคิวยังไม่ปรากฏให้รอการอัปเดตข้อมูลสักครู่
3. เปิดรายละเอียดคิวและแสดงตัวเลือกหรือข้อมูลสูตรที่มี
4. เปลี่ยนสถานะคิวตามปุ่มที่ระบบแสดง
5. หากมีเวลา เปิดส่วนตรวจสต็อกเพื่อแสดงจำนวนคงเหลือและสถานะใกล้หมด

**คำอธิบายประกอบ:** หน้าคิวอัปเดตด้วย polling ไม่ใช่ WebSocket และ Barista ดูข้อมูลสต็อกได้ แต่ไม่มีสิทธิ์แก้ไขสต็อก

### ขั้นที่ 3: ดูข้อมูลในหน้า Owner

1. สลับไปยังหน้า Owner
2. แสดงรายงานยอดขายและตัวกรองที่มี
3. แสดงคิวหรือข้อมูลสรุปที่หน้า Owner รองรับ
4. หากเหลือเวลา แสดงหน้า Menu Manager หรือ Inventory Manager

**คำอธิบายประกอบ:** ข้อมูลรายงานอาจอัปเดตเป็นรอบ ไม่ได้เปลี่ยนทันทีทุกครั้งที่มีการทำรายการ

## 3. ข้อควรพูดให้ตรงกับระบบ

- การเลือก `cash`, `transfer` หรือ `qr` เป็นการบันทึกวิธีชำระเงิน ระบบไม่ได้เชื่อมต่อ payment gateway เพื่อยืนยันเงินจริง
- เลขยอดขายหรือข้อมูล seed ใช้สาธิตการทำงาน อย่านำเสนอว่าเป็นยอดขายจริง
- หากแสดงผลทดสอบหรือ usability ให้ระบุช่วงเวลาและข้อจำกัดตามเอกสาร ไม่กล่าวอ้างว่าเป็นผลล่าสุดหากยังไม่ได้ทดสอบซ้ำ
- สต็อกจะถูกตรวจและตัดตามสูตรที่ตั้งไว้ สูตร seed เป็นข้อมูลตัวอย่างและอาจไม่ตรงกับสูตรจริงของร้าน

## 4. แผนสำรอง

หากระบบเปิดไม่ได้หรือการเชื่อมต่อมีปัญหา:

1. แจ้งผู้ฟังสั้น ๆ ว่าระบบสาธิตขัดข้อง
2. ใช้ภาพหน้าจอหรือวิดีโอสำรองที่เตรียมไว้
3. อธิบายลำดับการทำงาน Cashier → Barista → Owner จากสื่อสำรอง
4. ระบุให้ชัดว่าสื่อดังกล่าวเป็นภาพ/วิดีโอ ไม่ใช่การทำรายการสด
