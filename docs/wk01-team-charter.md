## 2. องค์ประกอบระบบเบื้องต้น (People, Process, Data, Hardware, Software, Network)

| องค์ประกอบ   | รายละเอียดในระบบร้านกาแฟ                                                                      |
| ------------ | --------------------------------------------------------------------------------------------- |
| **People**   | พนักงานหน้าร้าน (Cashier รับออเดอร์), บาริสต้า (ชงและดูคิว), เจ้าของ/ผู้จัดการร้าน (ดูรายงาน) |
| **Process**  | รับออเดอร์ → เลือกตัวเลือก → คำนวณราคา → ชำระเงิน → ออกเลขคิว → ชง → ส่งลูกค้า                |
| **Data**     | รายการเมนูและราคา, ตัวเลือก (ขนาด/หวาน/ท็อปปิง), ประวัติออเดอร์, ยอดขาย                       |
| **Hardware** | แท็บเล็ต/PC สำหรับ Cashier, จอบาริสต้า, เครื่องพิมพ์ใบเสร็จ (optional)                        |
| **Software** | React SPA (Frontend) + Node.js/Express API (Backend) + SQLite Database                        |
| **Network**  | Wi-Fi ภายในร้าน เชื่อม Client (Browser) กับ Server Port 3000 บนเครื่องเดียวกัน                |

## 3. แบบจำลอง SDLC ที่เลือกใช้ พร้อมเหตุผล

**แบบจำลองที่เลือก: Iterative**

เหตุผล:

1. **ขนาดทีมและระยะเวลา** — ทีม 3-5 คน ทำงานตลอด 16 สัปดาห์ วิชากำหนดให้มี 3 coding sprint (wk05, wk09, wk13) คั่นด้วย design sprint ซึ่งสอดคล้องกับ Iterative โดยตรง

2. **ความชัดเจนของ Requirement** — โจทย์ระบบร้านกาแฟมีขอบเขตชัดเจน (เมนู, POS, คิว) แต่รายละเอียดเพิ่งชัดขึ้นหลังเก็บข้อมูล จึงยังไม่เหมาะกับ Waterfall ที่ต้องการ Requirement ชัดตั้งแต่ต้น

3. **ความถี่ในการส่งมอบงาน** — วิชากำหนดให้ส่งงานทุกสัปดาห์ผ่าน GitHub เหมาะกับรอบส่งมอบสั้นของ Iterative

4. **ประสบการณ์ของทีม** — ทีมเป็นนักศึกษาที่เพิ่งเริ่มพัฒนาโครงงานจริง Iterative ให้โครงสร้างชัดเจนกว่า Agile/Scrum เต็มรูปแบบ
