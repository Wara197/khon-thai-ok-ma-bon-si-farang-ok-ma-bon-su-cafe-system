## 3. Use Case Description

### 01 รับออเดอร์และคำนวณราคา

| หัวข้อ            | รายละเอียด                                                                                                                                |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| **ชื่อ Use Case** | รับออเดอร์และคำนวณราคา                                                                                                                    |
| **Actor หลัก**    | พนักงานหน้าร้าน (Cashier)                                                                                                                 |
| **Actor รอง**     | บาริสต้า (ผู้รับออเดอร์ต่อ)                                                                                                               |
| **Description**   | พนักงานหน้าร้านรับคำสั่งซื้อจากลูกค้า เลือกรายการเมนูพร้อมตัวเลือก คำนวณยอดรวม บันทึกการชำระเงิน และส่งออเดอร์เข้าสู่คิวของบาริสต้า       |
| **Trigger**       | ลูกค้าสั่งเครื่องดื่มกับพนักงานหน้าร้าน                                                                                                   |
| **Precondition**  | 1) พนักงานเข้าสู่ระบบ POS แล้ว 2) เมนูที่เปิดขายพร้อมราคาแสดงอยู่ในระบบ                                                                   |
| **Postcondition** | ออเดอร์ถูกบันทึกพร้อมเลขออเดอร์/เลขคิวที่ไม่ซ้ำ ยอดสุทธิถูกต้อง วิธีชำระเงินถูกบันทึก สต็อกวัตถุดิบถูกตัด และออเดอร์ปรากฏบนหน้าจอบาริสต้า |

### Main Flow

1. พนักงานเปิดหน้าจอรับออเดอร์ ระบบแสดงเมนูที่เปิดขายพร้อมชื่อและราคา (FR-01)
2. พนักงานเลือกเมนูตามที่ลูกค้าต้องการ **«include» UC-02 เลือกเมนู ขนาด ความหวาน ท็อปปิง** (FR-02)
3. ระบบคำนวณราคาของแต่ละรายการโดยอัตโนมัติ (FR-05)
4. พนักงานกดยืนยันออเดอร์
5. ระบบตรวจสอบว่าข้อมูลที่จำเป็นครบถ้วน (FR-03)
6. ระบบสร้างเลขออเดอร์และเลขคิวที่ไม่ซ้ำกัน (FR-04)
7. ระบบคำนวณยอดสุทธิรวมส่วนลด/โปรโมชั่น (ถ้ามี) (FR-05)
8. พนักงานเลือกวิธีชำระเงิน **«include» UC-03 บันทึกวิธีชำระเงิน** (FR-06)
9. ระบบส่งออเดอร์ไปยังหน้าจอบาริสต้าพร้อมรายละเอียดครบถ้วนภายใน 5 วินาที (FR-07, NFR-02)
10. ระบบตัดสต็อกวัตถุดิบตามสูตรเครื่องดื่มอัตโนมัติ **«include» UC-05 ตัดสต็อกวัตถุดิบอัตโนมัติ** (FR-09)
11. ระบบออกบิล/ใบเสร็จ และจบ use case

### Alternative Flow

- **1 — แก้ไขรายการก่อนยืนยัน:** ที่ขั้นตอน 2 และ 3 หากลูกค้าขอเพิ่มรายการหรือเปลี่ยนรายการ พนักงานสามารถย้อนกลับไปแก้ไขตัวเลือกได้ก่อนกดยืนยันในขั้นตอน 4 โดยระบบคำนวณราคาใหม่ทุกครั้งที่มีการแก้ไข
- **2 — มีส่วนลด/โปรโมชั่น:** ที่ขั้นตอน 7 หากออเดอร์เข้าเงื่อนไขโปรโมชั่น ระบบคำนวณส่วนลดเพิ่มเข้าไปในยอดสุทธิก่อนดำเนินการต่อที่ขั้นตอน 8

### Exception Flow

- **1 — ข้อมูลที่จำเป็นไม่ครบ (เกิดที่ขั้นตอน 5):** เช่น ยังไม่เลือกขนาดเครื่องดื่มให้ระบบทำการแสดงข้อความแจ้งเตือนทันที และไม่อนุญาตให้ยืนยันออเดอร์จนกว่าพนักงานจะกรอกข้อมูลให้ครบ (อ้างอิง FR-03)
- **2 — วัตถุดิบไม่พอสำหรับเมนูที่เลือก (เกิดที่ขั้นตอน 10):** ระบบตรวจพบว่าสต็อกวัตถุดิบไม่พอสำหรับสูตรของเมนูนั้นจะให่ระบบแจ้งเตือน "วัตถุดิบไม่พอ" และไม่อนุญาตให้บันทึกออเดอร์รายการนั้น เพื่อไม่ให้รับออเดอร์ที่ทำไม่ได้
- **3 — ระบบขัดข้องขณะบันทึกออเดอร์ (เกิดที่ขั้นตอน 6–9):** การเชื่อมต่อกับฐานข้อมูล/เซิร์ฟเวอร์ล้มเหลวให้ ระบบแสดงข้อความแจ้งเตือนข้อผิดพลาด ไม่สร้างเลขออเดอร์ซ้ำซ้อน และให้พนักงานลองกดยืนยันใหม่อีกครั้งเมื่อระบบพร้อมใช้งาน

## 4.User Stories และ Acceptance Criteria

### Use story01 เรื่อง FR-01

**As a** พนักงานหน้าร้าน **I want** เห็นรายการเมนูที่เปิดขายพร้อมราคาทันทีเมื่อเปิดหน้าจอ **So that** พนักงานสามารถแจ้งราคาลูกค้าได้ถูกต้องโดยไม่ต้องถามหัวหน้างาน

- **AC1:** Given พนักงานเปิดหน้าจอรับออเดอร์ / When หน้าจอโหลดเสร็จ / Then ระบบแสดงรายการเมนูทั้งหมดที่สถานะ "เปิดขาย" พร้อมชื่อเมนูพร้อมราคาได้เลย
- **AC2:** Given เมนูบางรายการถูกปิดขายชั่วคราว / When พนักงานเปิดหน้าจอรับออเดอร์ / Then เมนูที่ปิดขายจะไม่ปรากฏในรายการให้เลือก

### Use story02 เรื่อง FR-02

**As a** พนักงานหน้าร้าน **I want** เลือกขนาด ระดับความหวาน และท็อปปิงของเครื่องดื่มนั้นๆได้ **So that** พนักงานบันทึกความต้องการของลูกค้าได้ครบถ้วนโดยไม่ต้องพิมพ์เอง

- **AC1:** Given พนักงานเลือกเมนูเครื่องดื่ม / When เปิดรายละเอียดสินค้า / Then ระบบแสดงตัวเลือกขนาด ระดับหวาน และท็อปปิงให้เลือกแบบกดปุ่ม
- **AC2:** Given พนักงานยังไม่เลือกขนาด / When พยายามเพิ่มรายการลงตะกร้า / Then ระบบไม่อนุญาตให้เพิ่มรายการจนกว่าจะเลือกขนาดครบ

### Use story03 เรื่อง FR-03, FR-04, FR-05, FR-07, FR-09 — Use Case หลัก Use case 01

**As a** พนักงานหน้าร้าน **I want** ให้ระบบคำนวณยอดรวมและสร้างเลขออเดอร์อัตโนมัติเมื่อฉันยืนยันออเดอร์ **So that** ฉันแจ้งราคาลูกค้าได้ถูกต้องรวดเร็วและออเดอร์ถูกส่งต่อให้บาริสต้าโดยไม่ตกหล่นเพื่อให้ได้งานที่มีประสิทธิภาพ

- **AC1 (Main Flow — สำเร็จ):** Given พนักงานเลือกเมนู ขนาด ความหวาน และท็อปปิงครบตามที่ลูกค้าต้องการ / When พนักงานกดยืนยันออเดอร์ / Then ระบบสร้างเลขออเดอร์/คิวที่ไม่ซ้ำ คำนวณยอดสุทธิถูกต้อง ตัดสต็อกวัตถุดิบ และส่งออเดอร์ไปหน้าจอบาริสต้าภายใน 10 วินาทีนั้น
- **AC2 (Exception E1 — ข้อมูลไม่ครบ):** Given พนักงานยังไม่ได้เลือกขนาดเครื่องดื่ม (ข้อมูลจำเป็นไม่ครบ) / When พนักงานกดยืนยันออเดอร์ / Then ระบบแสดงข้อความแจ้งเตือนว่าข้อมูลไม่ครบ และไม่สร้างออเดอร์จนกว่าจะกรอกครบ
- **AC3 (Exception E2 — วัตถุดิบไม่พอ):** Given วัตถุดิบที่ต้องใช้สำหรับเมนูที่เลือกมีไม่เพียงพอในสต็อก / When พนักงานพยายามยืนยันออเดอร์รายการนั้น / Then ระบบแจ้งเตือน "วัตถุดิบไม่พอ" และไม่อนุญาตให้บันทึกออเดอร์รายการนั้น

### Use story04 เรื่อง FR-06

**As a** พนักงานหน้าร้าน **I want** บันทึกวิธีชำระเงินของลูกค้า (เงินสด/โอน/QR) **So that** ยอดขายและรูปแบบการชำระเงินถูกบันทึกไว้ตรงกับความเป็นจริงเพื่อนำไปสรุปยอดในภายหลัง

- **AC1:** Given ออเดอร์ถูกยืนยันแล้วและรอการชำระเงิน / When พนักงานเลือกวิธีชำระเงินเป็น "QR Payment" / Then ระบบบันทึกวิธีชำระเงินเป็น QR และแสดงสถานะ "ชำระเงินแล้ว" หลังยืนยัน
- **AC2:** Given ออเดอร์ถูกยืนยันแล้ว / When พนักงานเลือกวิธีชำระเงินเป็น "เงินสด" / Then ระบบบันทึกวิธีชำระเป็นเงินสดและออกใบเสร็จได้ทันทีโดยไม่ต้องรอการยืนยันจากภายนอก

### Use story05 เรื่อง FR-07, FR-08

**As a** บาริสต้า **I want** เห็นรายการออเดอร์ใหม่ปรากฏพร้อมทั้งคิวรวมถึงรายละเอียดครบถ้วนและปรับสถานะได้ **So that** ฉันชงเครื่องดื่มได้ถูกต้องตามลำดับโดยไม่มีความล่าช้าและพร้อมแจ้งคิวผ่านจอทำให้ลูกค้ารู้คิว

- **AC1:** Given พนักงานหน้าร้านยืนยันออเดอร์ / When ออเดอร์ถูกบันทึกสำเร็จ / Then ออเดอร์ปรากฏบนหน้าจอบาริสต้าพร้อมเมนู ขนาด ความหวาน ท็อปปิง และเลขคิวภายใน 10 วินาที
- **AC2:** Given ออเดอร์อยู่ในสถานะ "รอทำ" / When บาริสต้ากดเปลี่ยนสถานะเป็น "กำลังทำ" แล้วเป็น "พร้อมรับ" / Then สถานะล่าสุดอัปเดตให้พนักงานหน้าร้านและลูกค้าเห็นทันที
- **AC3 (ข้อเพิ่มภายหลัง):** Given เจ้าของร้านกำหนดวิธีชงให้เมนู / When ออเดอร์ใหม่ของเมนูนั้นปรากฏในคิว / Then บาริสต้าเห็นวิธีชงบนการ์ดคิวโดยไม่ต้องค้นในหน้าคลัง และข้อความของออเดอร์ที่สร้างแล้วไม่เปลี่ยนเมื่อเจ้าของแก้คำแนะนำภายหลัง

### Use story06 เรื่อง FR-09

**As a** เจ้าของร้าน/ผู้จัดการ **I want** ให้ระบบตัดสต็อกวัตถุดิบอัตโนมัติและแจ้งเตือนเมื่อวัตถุดิบใกล้หมด **So that** ฉันสั่งซื้อวัตถุดิบเพิ่มได้ทันเวลาและไม่ขาดสต็อกระหว่างวัน

- **AC1:** Given ออเดอร์ถูกยืนยันสำเร็จ / When ระบบประมวลผลออเดอร์ / Then ระบบหักจำนวนวัตถุดิบตามสูตรของเมนูนั้นออกจากสต็อกโดยอัตโนมัติ
- **AC2:** Given ปริมาณวัตถุดิบคงเหลือต่ำกว่าค่า threshold ที่กำหนด (เช่น น้อยกว่า 10 หน่วย) / When ระบบตัดสต็อกเสร็จสิ้น / Then ระบบส่งการแจ้งเตือนไปยังบาริสต้าและเจ้าของร้านทันที

### Use story07 เรื่อง FR-10

**As a** เจ้าของร้าน/ผู้จัดการ **I want** ดูรายงานยอดขายรวม แยกตามสาขา และเมนูขายดีตามช่วงวันที่ที่เลือก **So that** ฉันวางแผนสต็อกและโปรโมชั่นได้ตรงกับพฤติกรรมการขายจริง

- **AC1:** Given เจ้าของร้านเลือกช่วงวันที่ต้องการดูรายงาน / When กดยืนยันช่วงวันที่ / Then ระบบแสดงยอดขายรวมและยอดขายแยกตามสาขาที่ถูกต้องตรงกับข้อมูลออเดอร์ในช่วงนั้น
- **AC2:** Given มีข้อมูลออเดอร์ในช่วงวันที่ที่เลือก / When เปิดรายงานเมนูขายดี / Then ระบบเรียงลำดับเมนูตามจำนวนที่ขายได้จากมากไปน้อยถูกต้อง

## ดำเนินการแก้ไข

ตัด **FR-09 (ตัดสต็อก)** ออกจาก US-03 ให้เหลือเฉพาะแกนหลักของ Use Case 01 คือ **FR-03, FR-04, FR-05, FR-07** เท่านั้น ส่วนการตัดสต็อกจริงยกให้เป็นหน้าที่ของ US-06 แต่ผู้เดียว

### Use story03 ฉบับปรับปรุง (FR-03, FR-04, FR-05, FR-07 — Use Case หลัก "รับออเดอร์และคำนวณราคา")

**As a** พนักงานหน้าร้าน **I want** ให้ระบบคำนวณยอดรวมและสร้างเลขออเดอร์อัตโนมัติเมื่อยืนยันออเดอร์ **So that** แจ้งราคาลูกค้าได้ถูกต้องรวดเร็วและออเดอร์ถูกส่งต่อให้บาริสต้าโดยไม่ตกหล่น

- **AC1 (Main Flow — สำเร็จ):** Given พนักงานเลือกเมนู ขนาด ความหวาน และท็อปปิงครบตามที่ลูกค้าต้องการ / When พนักงานกดยืนยันออเดอร์ / Then ระบบสร้างเลขออเดอร์/คิวที่ไม่ซ้ำ คำนวณยอดสุทธิถูกต้อง และส่งออเดอร์ไปหน้าจอบาริสต้าภายใน 10 วินาที
- **AC2 (Exception E1 — ข้อมูลไม่ครบ):** Given พนักงานยังไม่ได้เลือกขนาดเครื่องดื่ม / When พนักงานกดยืนยันออเดอร์ / Then ระบบแสดงข้อความแจ้งเตือนว่าข้อมูลไม่ครบ และไม่สร้างออเดอร์จนกว่าจะกรอกครบ
- **AC3 (Exception E2 — วัตถุดิบไม่พอ):** Given วัตถุดิบที่ต้องใช้สำหรับเมนูที่เลือกมีไม่เพียงพอในสต็อก / When พนักงานพยายามยืนยันออเดอร์รายการนั้น / Then ระบบแจ้งเตือน "วัตถุดิบไม่พอ" และไม่อนุญาตให้บันทึกออเดอร์รายการนั้น

**ผลหลังปรับปรุง:** Independent = ผ่าน, Estimable = ผ่าน, Small = **US-03 ผ่านครบทุกข้อ INVEST**
